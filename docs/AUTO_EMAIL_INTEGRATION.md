# Интеграция с `Email_horeca_send`

Проверено по фактическому `Code.gs` репозитория
`flycited2-dotcom/Email_horeca_send` 22 июля 2026 года. Парсер сам письма не
отправляет и не создаёт разрешение на рассылку.

## Какой файл использовать

Для рассылки предназначен **`outreach_ready.xlsx`**, а не полный
`master_all.xlsx`. В книге два листа:

- `Контакты` — единственный лист с колонкой `Email`, его импортирует Apps
  Script;
- `Метаданные` — версия, `run_id`, статистика и
  `approved_for_send=false`; колонки `Email` там нет, поэтому импортёр его
  пропускает.

Заголовки листа `Контакты` совпадают с реальным импортёром:

`Email`, `Название`, `Тип клиента`, `Город`, `Телефон`, `Сайт`, `Соцсеть`,
`Адрес`, `Источник`.

Дополнительные аудиторские колонки (`ID объекта`, `Доверие`, флаги и все
альтернативные контакты) импортёру не мешают.

В `outreach_ready` проходит одна строка на организацию, если:

- тип — целевой общепит;
- найден синтаксически валидный публичный email, не попавший в blacklist;
- confidence не ниже `OUTREACH_MIN_CONFIDENCE` (по умолчанию `0.70`);
- нет жёстких признаков шума;
- email не был получен только из слабого VK-наблюдения (такой контакт всегда
  остаётся в `outreach_review.csv` до ручного подтверждения);
- email ещё не занят другой, более качественной записью.

Все исключения с причиной остаются в `outreach_review.csv`, а полный набор —
в `master_all.*`. Альтернативные email/телефоны не теряются, но автоматически
выбирается только один основной email организации, чтобы не отправлять одно
предложение нескольким сотрудникам одновременно.

## Что изменить в Apps Script

В конфигурации `Email_horeca_send` нужны следующие значения:

```javascript
MASTER_FILE_NAME: 'outreach_ready.xlsx',
IMPORT_TYPES: [
  'ресторан', 'кафе', 'фастфуд', 'бар', 'паб', 'клуб', 'кофейня',
  'столовая', 'фудкорт', 'пиццерия', 'кондитерская'
],
TEST_MODE: true,
```

`MASTER_FOLDER_ID` должен указывать на папку, куда парсер загрузил
`outreach_ready.xlsx`. Текущий шаблон отправщика всё ещё содержит гостиничные
типы — без этой замены контакты общепита не импортируются.

До production дополнительно требуется approval gate по `run_id`: значение
`APPROVED_RUN_ID` в Script Properties должно точно совпадать с `run_id` на
листе `Метаданные`. Если значения нет или оно не совпало, импорт обязан
завершиться без добавления строк. Это не заменяется фактом загрузки файла в
Drive.

На 22 июля 2026 года это изменение подготовлено в отдельном локальном клоне
`Email_horeca_send`: файл/типы переключены, `TEST_MODE=true`, approval
проверяется до записи в лист рассылки, а `setupTriggers()` заблокирован в
тестовом режиме. Telegram-команда `/sample` в TEST_MODE также принудительно
отправляет только на `TEST_RECIPIENT`. Изменения пока не опубликованы, не
развёрнуты в Apps Script и не создают триггеры; следующий шаг — draft PR и
ручная приёмка в отдельной тестовой Drive-папке.

## Atomic handoff

После сборки парсер публикует в `output/handoff/` неизменяемые копии файлов и
атомарный `latest.json`. Handoff schema v3 содержит:

- SHA-256 полного master, outreach-файлов и отдельного quarantine;
- `run_id`, число строк, состояние и причины ошибок;
- отдельные idempotency keys для master, outreach и quarantine;
- `quarantine.automation_eligible=false`; consumer не должен извлекать из
  quarantine адресатов или crawler seed-ы;
- `approved_for_send=false` и `auto_send_allowed=false`.

Consumer должен проверять checksum, `state=ready_for_review`, отсутствие
failures и отдельное ручное одобрение именно этого `run_id`/checksum. Повторный
import хранит idempotency key с unique constraint; на уровне получателя нужен
дополнительный ключ `campaign_id + normalized_email`.

## Порядок безопасной приёмки

1. Запустить парсер с `AUTO_UPLOAD=0`; проверить `run_summary.json`, master,
   `outreach_review.csv` и случайную выборку `outreach_ready.xlsx`.
2. Загрузить файл в отдельную тестовую папку Drive.
3. В отправщике оставить `TEST_MODE=true`, удалить/не создавать production
   triggers и указать только собственный `TEST_RECIPIENT`.
4. Одобрить конкретный тестовый `run_id`, выполнить только импорт и создание
   1–3 тестовых черновиков.
5. Проверить подстановки, Reply-To, отписку/suppression, баунсы и отсутствие
   дублей.
6. Production-рассылку включать только отдельным решением владельца процесса.

Telegram-доставка, наличие файла в Google Drive, успешный парсинг или
созданный черновик сами по себе не являются разрешением отправлять письма.
